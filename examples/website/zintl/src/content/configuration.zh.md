# 配置

每个选项、它改变什么，以及你什么时候会用到它。

## 语言

| 选项             | 类型       | 默认值             | 作用                             |
| :--------------- | :--------- | :----------------- | :------------------------------- |
| `locales`        | `string[]` | —                  | 本项目构建的全部语言。必填。     |
| `sourceLocale`   | `string`   | `locales` 的第一项 | 你书写所用的语言。永不写入磁盘。 |
| `pendingLocales` | `string[]` | `[]`               | 会被维护和校验，但不会发布。     |

## 各样东西放在哪里

| 选项            | 类型                        | 默认值                          | 作用                                                                     |
| :-------------- | :-------------------------- | :------------------------------ | :----------------------------------------------------------------------- |
| `outputDir`     | `string`                    | `"./zintl"`                     | 目录写入的位置，相对项目根目录。                                         |
| `catalogFormat` | `string \| (ctx) => string` | `<path>[.<func>].<locale>.json` | 目录命名。可用记号：`[locale] [path] [dir] [name] [func] [bId] [hash]`。 |
| `metadataDir`   | `string`                    | `node_modules/.zintl`           | 编译器自己的账簿。不是你该编辑的东西。                                   |

## 代码之外的内容

| 选项            | 类型                              | 默认值          | 作用                                                         |
| :-------------- | :-------------------------------- | :-------------- | :----------------------------------------------------------- |
| `assetsTarget`  | `(string \| AssetTargetConfig)[]` | `["md", "txt"]` | 内容随语言而变的文件。单独写扩展名等价于 `**/*.<ext>`。      |
| `virtualAssets` | `boolean`                         | `false`         | 通过虚拟模块交付本地化资源，而不是把导入解析到磁盘上的产物。 |

被列为目标的资源是按语言**撰写**的，而不是被翻译出来的。如果一个文件在所有语言里都一样，就不要把它列为目标。

它如何抵达浏览器，取决于你的导入方式而不是扩展名：

```ts
import text from "./about.txt?raw"; // 内容本身，内联进目录
import url from "./hero.webp"; // 打包器为该语言产物给出的 URL
```

两者都会在运行时跟随语言，因此切换语言会重新指向导入，而无需重新加载。

## 维护

| 选项                  | 类型      | 默认值                        | 作用                                               |
| :-------------------- | :-------- | :---------------------------- | :------------------------------------------------- |
| `prune`               | `boolean` | `true`                        | 当没有源字符串再产生某个键时，把它从目录中移除。   |
| `similarityThreshold` | `number`  | `0.6`                         | 修改后的字符串要多相似才能保留原译文。调低更宽容。 |
| `verifyIntegrity`     | `boolean` | 构建时 `true`，开发时 `false` | 缺失翻译时让构建失败。                             |

> [!IMPORTANT]
> `verifyIntegrity` 正是让缺失的翻译弄坏构建、而不是渲染成空白的那个开关。Zintl 在设计上没有回退到源语言的路径——这道检查会在你的用户之前发现缺口。它同样覆盖本地化资源：空的产物就是一条以文件为身体的缺失翻译。

## 什么算作可翻译字符串

字符串在抵达**汇点**时被提取——汇点是已知面向用户的位置。汇点由切面声明，所以你的项目提取什么，取决于哪些切面处于活动状态。

| 形式                    | 匹配                            |
| :---------------------- | :------------------------------ |
| `jsx:<element>:<attr>`  | 一个 JSX 属性；`*` 表示任意元素 |
| `html:attr:<attr>`      | HTML 或 SFC 模板中的属性        |
| `dom:<receiver>:<prop>` | 对某个属性的赋值                |
| `obj:<binding>:<field>` | 具名对象的字段                  |
| `call:<fn>:<field>`     | 传入该调用的对象的字段          |
| `tag:<fn>`              | 承载标记的带标签模板字面量      |

HTML 文档、SFC 模板与 JSX 子节点中的纯文本不需要描述符——它就是标记中的文本，这本身已是证据。

默认里**刻意没有 `obj:field:*`**。在任意对象上匹配字段名对该对象一无所知，于是 `{ label: "signup_click" }` 会像任何标签一样被提取。请改为指名对象：

```ts
const ui = { home: { title: "Welcome" } }; // obj:ui:title
defineConfig({ title: "My site" }); //        call:defineConfig:title
```

用 `additionalTargets` 在活动切面已发现的基础上追加，用某个切面自己的 `targets` 替换该切面所贡献的内容。

## 扩展它

| 选项                | 类型                  | 作用                                |
| :------------------ | :-------------------- | :---------------------------------- |
| `facets`            | `(string \| Facet)[]` | 组合框架、打包器与内容方面的行为。  |
| `additionalTargets` | `string[]`            | 追加汇点描述符，不替换任何已有项。  |
| `multiplex`         | `boolean`             | 每种语言一份 HTML 文档。仅限 Vite。 |
| `debug`             | `string`              | 追踪编译器的某个子系统。            |

配置一个属于你已替换掉的切面的选项，是硬错误，而不是一个悄无声息什么都不做的设置。

# الجمع والقواعد

للإنجليزية صيغتا جمع. وللعربية ست. ولا ينبغي لشيفرتك أن تعرف ذلك.

## المشكلة، مرة واحدة

```ts
const label = `${count} items`;
```

هذا خطأ في معظم اللغات، والحلول المعتادة تزيد مصدرك سوءًا: شرط ثلاثي لا يغطي إلا حالتين، أو استدعاء `t()` بوسيط `count` ومفتاحٍ صار عليك أن تسميه.

## ما يفعله زينتل بدل ذلك

أنت تكتب الجملة. والمترجمون يكتبون القواعد، في الكتالوج، بصيغة ICU:

```json
{
  "{count} items": "{count, plural, zero {لا عناصر} one {عنصر واحد} two {عنصران} few {# عناصر} many {# عنصرًا} other {# عنصر}}"
}
```

مصدرك يظل يقول `${count} items`. الكتالوج العربي يحمل ست صيغ لأن للعربية ستًا، والإنجليزي لا يحمل أيًّا لأن الإنجليزية لا تحتاجها. التعقيد النحوي يسكن حيث تسكن القواعد.

## وهي تُصرَّف حتى تختفي

نص ICU ذاك لا يُحلَّل في المتصفح. فوقت التصريف يصير دالّة جافاسكربت عادية:

```js
(params) => {
  const { count } = params;
  if (count === 0) return "لا عناصر";
  if (count === 1) return "عنصر واحد";
  // …
};
```

فلا تصل أي مكتبة لتنسيق الرسائل إلى مستخدميك. ومحرك نحوي يُشحن إلى كل زائر ليحسم قاعدة كانت معروفة وقت التصريف هو بالضبط نوع الثقل الذي وُجد هذا المشروع لإزالته.

## الاختيار بين صياغتين

`select` يعمل بالطريقة نفسها، لكل ما ليس عددًا:

```json
{
  "Invite them": "{gender, select, male {ادعُه} female {ادعُها} other {ادعُهم}}"
}
```

## حين لا يملك المصدر تلك الكلمة

تحتاج العربية إلى معرفة جنسٍ لم تذكره جملتك الإنجليزية قط. وبدل لَيّ الإنجليزية لتمنح المترجم شيئًا يتعلق به، مرّر القيمة على نحو غير مرئي:

```ts
// @zintl-pass gender={user.gender}
const invite = `Invite them`;
```

يبقى المصدر مقروءًا كما كان تمامًا. ويظهر `gender` في المخطط المولَّد، فيستطيع المترجمون التفريع عليه.

> [!NOTE]
> هذا هو منفذ الخروج لحقيقة أن لغات الهدف كثيرًا ما تحتاج سياقًا أكثر مما يملكه المصدر. وبدونه، الحل المعتاد هو إفساد إنجليزيتك لخدمة لغة لم تُكتب بها.

## الأرقام والتواريخ والعملات

تلك مهمة `Intl`، و`Intl` موجود في المتصفح أصلًا. وزينتل لا يغلّفه.

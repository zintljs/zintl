# 语言与切换

你传给 `zintl()` 的东西，决定了你的应用有多少部分在编译期仍未确定。

## 变量还是字面量

```ts
await zintl(locale); // 变量：语言是运行时的决定
await zintl("fr"); //  字面量：语言是编译期的事实
```

它们编译成两个不同的应用。

|                    | `zintl("fr")` | `zintl(locale)` |
| :----------------- | :------------ | :-------------- |
| 产出目录分块       | 无            | 有              |
| 构建其他语言       | 否            | 是              |
| 包中含源语言字符串 | **没有**      | 有              |

注意最后一行。用字面量时，你的英文文本根本不在产物里。页面不是*回退*到英文——英文压根没有被构建。

**用字面量**，当一个页面确实只有一种语言：按语言分别静态构建、本地化的落地页、每种语言各生成一次的路由。

**用变量**，只要用户可以切换语言，或者语言来自 URL、cookie、请求头或偏好设置。

> [!WARNING]
> 弄反了是静默的。带语言切换器的应用如果用了字面量，构建照样通过，然后就是切不动——因为其他语言从未被产出。

## 运行时切换

再次调用宏：

```ts
await zintl("ar");
```

目录会就地替换，store 随即通知所有监听者。屏幕能否不重载就重绘，取决于你的框架而非 Zintl：组件会重新读取目录的框架就地重绘，没有这套机制的框架则拒绝该更新并重新加载。两种情况下结果都是正确的。

Zintl 会直接在文档上设置 `lang` 与 `dir`，所以从右到左的书写方向随语言一同到来，你不需要第二份样式表——写 `margin-inline-start` 而不是 `margin-left`，布局自会镜像。

当前语言会被记住，并在你的路由带有语言段时（`/ar/guide`）从路径的第一段读回。如果你希望链接可分享，就把语言放在 URL 里。

## 每种语言一份文档

当每条路由都只有一种语言时，就把它们全部构建出来：`multiplex` 选项会把你的 HTML 展开成每种语言一份文档，各自固化那一种语言，别的什么都不带。

这是营销站点，或不需要页内切换器的文档站点该选的形态。目前它仅限 Vite——Rsbuild 没有展开能力。

## 让一种语言先立起来

一种你还在翻译的语言，不必因此弄坏构建，也不必因此抵达用户。`pendingLocales` 列出正在进行中的语言：它们的目录会被维护和校验，但不会被发布。

这是「我们很快会加上日语」的诚实版本——字符串是真的，文件是真的，而没有人会被送上一个翻译到一半的页面。

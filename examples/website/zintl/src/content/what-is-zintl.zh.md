# 什么是 Zintl

Zintl 是一个编译期国际化引擎。你只管写普通字符串；编译器会找到它们，算出每个页面真正需要哪些，然后只发送这些。

## 全部的 API

```ts
import { zintl } from "zintljs/macro";

await zintl(userLocale);

document.querySelector("#app").innerHTML = `<h1>Welcome back!</h1>`;
```

这不是节选。没有 `t()` 要把标题包进去，没有键要为它起名，也没有字典要手动同步。

## 为什么这样可行

大多数 i18n 库在运行时工作，所以必须有人告诉它们存在哪些字符串——而唯一的告知方式，就是在每个用到的地方标记它。Zintl 则在你的应用运行之前，用解析器读取源码。存在哪些字符串、哪个页面能够到达它们，这两件事都可以在编译期算出来。

一旦掌握了这两个事实，翻译就不再是查表问题，而变成了**打包**问题。Zintl 其余的一切，都从这个视角转换中来。

## 由此得出的结论

**你的翻译按代码的方式分割。** 一次 `zintl(locale)` 调用标记一个*信任锚点*——你的应用在此决定自己处于哪种语言。从该锚点可达的一切构成一个*边界*，而一个边界会成为一个目录分块。打开你设置页的人，下载的是设置页的翻译。不是全部翻译。

**不使用的东西不会被发送。** 复数与性别规则会编译成普通的 JavaScript 条件语句，因此没有任何语法引擎会进入浏览器。你的源语言根本不会被写入磁盘——编译器本来就有这些字符串。

**重构是免费的。** 身份基于内容而非路径，所以移动文件或重命名组件不会造出新的键。重构一个应用，通常事后还要花一天去核对目录。在这里，这件事不花任何代价。

## 它对你的要求

缺失的翻译是构建错误，不是回退。

> [!IMPORTANT]
> Zintl 绝不会用你的源语言去顶替缺失的翻译。没有回退路径可供开启，这是刻意的设计：静默回退是一种会以功能的面目抵达用户的缺陷。

这是 Zintl 比你大概习惯的做法更严格的唯一一处，而且是有意为之：那个本该发现问题的检查，被放在你的构建里，而不是放在生产环境里。
